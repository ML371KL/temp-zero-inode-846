# Модели 850: хаб справедливых стоимостей российских акций

Одна страница для всех моделей семейства «850»: Магнит, X5, Лента, Сбербанк,
Т-Технологии и следующие (по одной в неделю, цель — около 55). Хаб ничего не
считает заново. Он читает выпуск каждой модели через её публичную дверь
`/api/model`, сводит главное в одну таблицу и ведёт на экраны самой модели.
Сами модели и их дашборды хаб не трогает.

- Адрес: **https://tzi-846.pages.dev**, вход по паролю. Пароль спрашивается
  один раз, дальше устройство запоминается.
- Код и выкладка — этот репозиторий. История оценок — его ветка `history`
  (пишется автоматически).

## Что на хабе и почему

Хаб отвечает на четыре вопроса. На каждый — свой экран.

| Экран | Вопрос | Что показано |
|---|---|---|
| **Обзор** | Где сегодня самый большой разрыв между моделью и рынком и насколько модель в нём уверена? | Четыре плитки (сколько моделей и из скольких задуманных; медианный потенциал; самый большой разрыв; ближайший отчёт). Главная таблица: по строке на акцию — рынок, медиана модели, потенциал, **полоса к рынку**, P(справедливая < рынка), медиана целей брокеров, следующий дивиденд, ближайший отчёт, свежесть выпуска |
| **Карта** | Какие разрывы надёжные, а какие — при широкой неопределённости? | Точечная диаграмма: по горизонтали потенциал, по вертикали ширина полосы 80 % в процентах медианы, размер точки — капитализация. Рядом табличный двойник по отраслям |
| **Календарь** | Что впереди? | Отчёты, дивиденды, решения ЦБ и другие макро-входы из календарей всех моделей. Повторы склеены, у отчёта, которого ждёт модель, стоит метка «факт модели» |
| **Модели** | Всё ли в порядке с самими моделями? | Каталог: свежесть выпуска, книга допущений, дата фактов, какой отчёт ждёт модель, предупреждения выпуска, ссылки на все экраны модели; строки «в работе» |

Почему так:

- **Полоса к рынку — главный рисунок.** Каждая модель печатает не точку, а
  распределение: медиану и полосы 50/80 % по суждениям книги. Чтобы
  сравнить 50 акций с ценой от 1 ₽ до 10 000 ₽, полосы пересчитаны в
  проценты к рыночной цене. Шкала общая для всех строк, оранжевая линия «рынок» —
  ноль. Видно сразу и знак разрыва, и уверенность модели: у Ленты узкая
  полоса целиком правее рынка, у Магнита — широкая, поперёк рынка.
- **Потенциал = медиана модели / рыночная цена − 1.** Это единственное число,
  которое хаб считает сам. Всё остальное берётся из выпусков как есть, а
  нераскрытое остаётся «—» (правило семейства `null ≠ 0`).
- **Ничего не прячется.** Строка раскрывается по клику и показывает оценку
  (полосы, точку, вклад взгляда на ставки, миры N/H/M), рынок (цену,
  капитализацию, мультипликаторы, брокеров, дивиденд), события компании,
  данные выпуска, график «медиана и рынок во времени» и кнопки на все экраны
  модели.
- **Свежесть видна везде.** Точка у названия и фишка в шапке: зелёная —
  выпуск свежий, жёлтая — у выпуска предупреждения (так же, как фишка на
  дашборде модели), красная — выпуску больше 96 часов или модель не отвечает.
  Жёлтый считается по правилу фишки на витрине самой модели, а оно у
  контрактов разное: таблица `CHIP_RULES` в `functions/_lib/summarize.js`.
  У Т и Сбера закрытый квартал книги до отчёта за него — справка, а не
  тревога; желтят вышедший и не внесённый отчёт, просроченный ручной вход и
  отставание книги больше чем на квартал. Витрина меняет правило фишки —
  меняется и её строка в `CHIP_RULES`, иначе цвета разойдутся.
- **Масштаб на 50–60 акций.** Фильтр по отраслям, поиск по названию и тикеру,
  сортировка по любому столбцу, группировка по отраслям. На телефоне таблица
  превращается в карточки.
- **Плитка компании — знак и цвет из реестра.** У каждой строки квадратная
  плитка одного размера: одна-две буквы на цвете, с которым компанию узнают
  (зелёная «С» — Сбербанк, жёлтая «Т» — Т-Технологии). Хаб рисует её сам:
  без логотипов, файлов и запросов к витринам, так что новая модель получает
  плитку той же записью реестра.
- **Стиль семейства.** Те же токены, шрифты, палитра (синий — модель,
  оранжевый — рынок) и правило темы: с 20:00 до 07:00 тёмная. Хаб выглядит
  частью той же линейки, что и дашборды моделей.

## Как это устроено

```
 браузер ──(cookie)──► Cloudflare Pages tzi-846
                         functions/_middleware.js   пароль, CSP, граница /api/
                         /api/registry              registry.json (живой с GitHub или вшитый)
                         /api/card/<slug>  ──────►  <модель>/api/model  (запасные: data[] реестра)
                                                    └ сводка 3–8 КБ (functions/_lib/summarize.js), кэш края 2 мин
                         /api/history/<slug> ────►  ветка history этого репозитория
 GitHub Actions snapshot (2 раза в день) ──────────► ветка history: медиана, полосы, цена каждой модели
```

- **Одна модель — один запрос.** Браузер просит карточки параллельно, каждая
  функция делает 1–3 подзапроса и разбирает один выпуск (≈1–2 мс CPU). Так
  хаб укладывается в лимиты бесплатного тарифа и при 60 моделях.
- **Устойчивость.** Если дашборд модели лежит, берётся запасной адрес данных
  из реестра. Если и его нет — последняя годная карточка из кэша края с
  пометкой. Если нет и её — строка «нет данных» с причиной: остальной хаб
  работает.
- **Разные контракты.** Выпуски моделей устроены по-разному (`magnit-v5.1`,
  `x5-v1`, `lenta-v1`, `sber-v1`, `t-v1`). Сводка читает общий путь семейства
  (`fair_value.headline`) с запасными путями. Модель, собранная по образцу
  Ленты или Сбера, читается без правок хаба (раздел «Совместимость»).

## Пароль и «запомненное устройство»

- Пароль — секрет `HUB_PASSWORD` проекта Cloudflare Pages. В репозитории его
  нет. Если секрет не задан, хаб закрыт целиком (503), а не открыт.
- Верный пароль один раз → подписанная cookie (`HttpOnly`, `Secure`,
  `SameSite=Lax`) на 400 дней, это максимум, который хранят браузеры. При
  каждом заходе cookie продлевается, поэтому устройство, где хаб открывают
  хотя бы раз в 400 дней, пароль больше не увидит.
- Сбросить:
  - **одно устройство** — кнопка «Забыть это устройство» внизу хаба;
  - **все устройства** — сменить `HUB_PASSWORD` или поднять
    `HUB_SESSION_EPOCH` в `wrangler.toml` (1 → 2) и перевыложить.
- Перебор сдерживается: 10 неверных попыток за 15 минут с одного IP — пауза
  до конца окна.
- Хаб закрыт от индексации (`noindex`, `robots.txt`), кэш — только
  приватный, ссылки на модели уходят без `Referer`.

## Первый запуск (один раз)

Сейчас хаба ещё нет в Cloudflare: проект `tzi-846` создаётся первой
выкладкой. Есть два пути.

**А. Автоматически через GitHub Actions (рекомендуется).** После этого любой
push в основную ветку выкладывает хаб сам.

1. В Cloudflare создать отдельный токен для этого репозитория: *My Profile →
   API Tokens → Create Token → Create Custom Token*, право
   **Account → Cloudflare Pages → Edit**, в *Account Resources* — свой
   аккаунт. Значение токена Cloudflare показывает один раз, его нужно сразу
   скопировать. Account ID — *Workers & Pages* → правая колонка
   *Account details* (он же — 32 символа в адресе дашборда после
   `dash.cloudflare.com/`; или `npx wrangler whoami` на ноутбуке).
2. В GitHub-репозитории: *Settings → Secrets and variables → Actions → New
   repository secret*:
   - `CLOUDFLARE_API_TOKEN` — токен;
   - `CLOUDFLARE_ACCOUNT_ID` — Account ID;
   - `HUB_PASSWORD` — пароль хаба.
3. *Actions → deploy → Run workflow* (или любой push в основную ветку).
   Workflow создаст проект `tzi-846`, положит пароль в секрет проекта и
   выложит хаб на https://tzi-846.pages.dev.
4. *Actions → snapshot → Run workflow* — первая точка истории (дальше
   снимки идут сами дважды в день).

**Б. С ноутбука, как выкладываются модели:**

```bash
npx wrangler@4.135.0 pages project create tzi-846 --production-branch main   # только первый раз
npx wrangler@4.135.0 pages secret put HUB_PASSWORD --project-name tzi-846   # спросит пароль
npx wrangler@4.135.0 pages deploy web --project-name tzi-846 --branch main
```

## Новая модель — раз в неделю

Достаточно добавить запись в `registry.json` и закоммитить её в основную
ветку. Хаб читает реестр с GitHub (`REGISTRY_URL`), поэтому строка появится
примерно через 5 минут, без перевыкладки. При выкладке через Actions хаб
заодно перевыложится сам.

```json
{
  "slug": "gazp",
  "name": "Газпром",
  "tickers": ["GAZP"],
  "sector": "Нефть и газ",
  "mark": "Г",
  "color": "#0079c2",
  "url": "https://tzi-850-gazp.pages.dev",
  "aliases": ["Газпром"],
  "data": ["https://ml371kl.github.io/temp-zero-inode-850-gazp-data/latest.json"],
  "status": "live"
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `slug` | да | латиница, цифры, дефис; ключ в адресах `/api/card/<slug>` и `#overview/<slug>` |
| `name` | да | имя компании на хабе |
| `url` | для `live` | адрес дашборда модели (https), у которого есть `/api/model` |
| `tickers` | желательно | первый — основной: его цена считается «рынком» строки |
| `sector` | желательно | отрасль: фильтр, группы, карта |
| `mark` | желательно | знак на плитке компании, 1–3 символа (`С`, `X5`); нет — первые две буквы основного тикера |
| `color` | желательно | цвет плитки, с которым компанию узнают (`#rrggbb`); нет — нейтральная серая плитка |
| `ink` | нет | цвет знака (`#rrggbb`), если нужен не белый и не чёрный (жёлтая «Л» Ленты) или белый на среднем тоне (Сбербанк); нет — белый или чёрный, что контрастнее к плитке |
| `aliases` | желательно | как компанию называют в заголовках событий чужих календарей (иначе отчёт X5 из календаря Магнита припишется Магниту) |
| `data` | нет | запасные адреса того же выпуска (raw или Pages репозитория данных) |
| `status` | нет | `live` (по умолчанию) или `planned`: модель «в работе» видна в каталоге без чисел |
| `added`, `note` | нет | дата появления (ГГГГ-ММ-ДД) и короткая пометка для каталога |

`target` в корне реестра — сколько моделей задумано (сейчас 55). Это
знаменатель плитки «Моделей в хабе».

## Совместимость: что хаб читает из выпуска

Новая модель читается без правок хаба, если её `/api/model` отдаёт хотя бы:

| Путь выпуска | Для чего |
|---|---|
| `schema`, `meta.published_at` (или `generated_at`), `meta.valuation_date`, `meta.facts_date`, `meta.book_version`, `meta.payload_sha256` | выпуск и свежесть |
| `fair_value.headline.{median, printed_median, band80, band50, printed_band80, printed_band50, point, printed_point, p_below_market, market}` | оценка и полоса (у X5 те же числа лежат в `headline.{central, band, inner, …}`, и это тоже читается) |
| `market.price`, `market.price_date` (или `market.prices.<тикер>`) | рынок |
| `calendar.events[]` (`date`/`when`, `title`, `kind`/`id`, `precision`, `covers`), `calendar.next_fact` | календарь и «ближайший отчёт»; отчёт за один месяц (`covers` вида `2026M09`: РСБУ Сбера, операционный релиз Т) — мелкое событие, в «ближайший отчёт» не идёт |
| по желанию: `market.sellside`/`market.brokers`, `dividends.next_expected`, `market.multiples`, `fair_value.by_world`, `valuation_history` | брокеры, дивиденд, мультипликаторы, миры, история |
| по желанию: `live.degraded_flag`, `checks.flags`, `checks.gates` (с `fired`), `gates` в корне, `meta.book_first_period_closed`, `meta.periods_closed` | предупреждения выпуска и жёлтая точка — по `CHIP_RULES` |

Если поля нет, в хабе стоит «—». Если путь иной, его добавляют в
соответствующий `pick…` в `functions/_lib/summarize.js` и закрепляют тестом
на фикстуре (`node tools/trim-fixture.mjs выпуск.json > tests/fixtures/<slug>.json`).

## Структура

| Путь | Что |
|---|---|
| `registry.json` | реестр моделей — единственный список того, что показывает хаб |
| `web/` | статика без сборки: `index.html`, `app.js` (ванильный JS), `styles.css`, `_routes.json` (все запросы — через функции, иначе статика была бы открыта без пароля) |
| `functions/_middleware.js` | пароль, граница `/api/`, заголовки безопасности |
| `functions/login.js`, `logout.js` | вход и «забыть устройство» |
| `functions/api/registry.js`, `api/card/[slug].js`, `api/history/[slug].js` | двери данных хаба |
| `functions/_lib/` | `summarize.js` (сводка выпуска), `sources.js` (чтение выпуска и вкладок модели), `registry.js`, `history.js`, `auth.js`, `pages.js` (страницы входа), `csp.js` |
| `tools/snapshot.mjs` | снимок истории (его запускает `.github/workflows/snapshot.yml`) |
| `tools/trim-fixture.mjs` | фикстура теста из выпуска модели |
| `tests/` | `node --test`: сводка пяти контрактов, пароль и ворота, двери данных, история, статика |
| `.github/workflows/` | `ci.yml` (тесты и сборка функций), `deploy.yml` (выкладка), `snapshot.yml` (история) |
| `wrangler.toml` | проект Pages и переменные (`REGISTRY_URL`, `HISTORY_BASE_URL`, `HUB_SESSION_EPOCH`) |

## Локально

```bash
npm test                                                      # 36 тестов, без зависимостей (Node ≥ 20)
npx wrangler@4.135.0 pages dev web --binding HUB_PASSWORD=dev # http://localhost:8788, пароль «dev»
node tools/snapshot.mjs --dir /tmp/history                    # снимок истории в каталог
```
